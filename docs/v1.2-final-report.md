## 问题 1：对话规模极大时消息发送可能不成功

**已修复。**

- **R1（主因）内核请求端零上下文治理**：`dsh-agent-loop` 每 step 全量 `deriveMessages()`，超限即 provider 拒绝当轮终局，规模严格单调。修复 = `patches/@deepseek-ai__dsh-llm-pi-ai@0.1.1-rc.2.patch` 第三个中性 globalThis 门 `__recApplyContextBudget`（零行为差异条件：未登记会话/预算非法/条数未超 → 原样透传），配 `src/main/kernel/contextBudget.ts`：按 `options.sessionId`（=话题 id）解析预算，裁剪窗口对齐最近真实用户消息（含紧邻回合快照），fail-safe 永不抛错。链路：话题注册表 `contextCount`（建册+发送刷新+fork 复制）→ `dshTopicSend`/`dshTopicCreate` IPC 三层（preload 类型、handler 白名单校验、`TopicSendOptions`）→ 渲染层 `assistantContextCount()` 折算（与 MessagesService 同一哨兵值语义）随每次发送上行。8 个单元测试（裁剪定位、fail-safe、幂等装卸）。
- **R2① 话题队列默认并发**：`queue.ts getTopicQueue` 默认 `concurrency: 1`。一个话题=内核一个会话=单槽投影；并发>1 时 `pendingStubs` 互踩导致 turn/start 认领错 stub（并答串模型）。多模型并答按队列顺序逐个流式。
- **R2② startTurn 静默 return**：`kernelChat.ts` stub 缺失时补 warn 取证；终态收口交给 R6-4。
- **R3 发送热路径 dispose+整会话 resume**：`topics.ts computeMcpSignature` 改返回 `{signature, anyUnreachable}`——MCP 服务器瞬时失联不再翻转签名放大成每轮 dispose+O(n) 重放；运行中回合不拆活体（`isTopicRunning` 守卫），漂移留给下一轮。
- **R6 静默失败四件**：① `messageThunk.ts` 触发消息找不到 → throw 进既有终态（原来话题永远转圈）；② `Inputbar.tsx` 发送失败 → toast `error.message_send_failed`，输入保留；③ `checkRateLimit` 改按调用方话题；④ `kernelChat.ts finishTurn` 无状态分支 → 孤儿 stub 落 ERROR 终态 + loading 复位。

**有证据不是问题（R4 三件）**：`useTopicGenerating` O(n) 扫描（唯一订阅者，常数极小；结构化 flag 违反"第二真相源"禁令）；`assistants.flatMap`（每回合一次）；逐事件 broadcast（速率受 token 流上限约束，批处理破坏实时投影）。

**不修（R2③ stub 键带回合身份）**：并发=1 后 stub 键冲突不再可能，加回合身份是冗余复杂度。

## 问题 2：文件管理偶发找不到/无法定位文件

无单一元凶，四类结构性缺陷叠加（全文见调查报告第 7 节已排除项）。**已修复：**

- **候选 1 路径地基竞态**：`FileManager.syncRuntimePaths()` 幂等+重试 2 次；主窗口 `useAppInit` 与 **mini 窗口**（此前从不拉 getAppInfo，小窗路径重建全坏）启动时调用；`FileList`/`ImageBlock` 订阅 `runtime.filesPath`，路径晚到重渲染，不再挂注定裂图的 `file://` URL。
- **候选 2 定位/打开静默吞错**：`FilesPage.handleOpenFile` 失败 toast；`FileList` 图片 `onError` 落 `FailedPlaceholder`（不再永远转圈）；打开/删除/加载失败全有用户可见信号。
- **候选 3 ext 丢点**：`FileStorage.saveBase64Image/savePastedImage` 返回带点 ext（仓库契约=带点）；`repairDotlessExtRows()` 启动修复历史行；`kernelImages` mime 查表先剥点。
- **候选 4 BackupManager**：① 备份空壳 `Data/` 目录不再创建（还原侧按"存在且非空"判定）；② LevelDB 直拷加 EBUSY/EPERM 瞬时锁重试（一致性局限记入 `docs/limits-and-baseline.md` 有意保留表）；③ 启动还原失败弹窗告知（备份副本保留、下次启动自动重试），不再静默。
- **候选 5 findDuplicateFile 双扩展名**：`name` 不再拼出 `uuid.png.png`；`origin_name` 透传原始名。
- **候选 6 引用计数漂移**：内核图片幂等登记保留现计数（回放非新引用），不再一次删除提前清行清字节。
- **候选 7 删除链路**：先删字节后删行（字节删失败可重试不吞错）；字节缺失按幂等成功+warn 取证。

## 问题 3：生图界面无法正常上传参考图

**已修复。** 根因：参考图从未上传入仓——绘画 composer 的 `materializeInputs` 只在 Dexie 登记元数据（`addFile`），不拷字节（聊天侧发送前有 `FileManager.uploadFiles`，绘画侧没有）。后果是缩略图裂图 + generate 时 `readBinaryImage` ENOENT 裸抛（在 try 之前）→ REMOTE_ERROR 弹原始路径，请求从未发出。选图/粘贴/拖拽三入口全命中。

- `materializeInputs`：不在仓的 chip 调 `FileManager.uploadFile` 真正入仓并用返回元数据替换托盘 chip；已入仓（SEED 回灌/历史输入）只计引用；失败摘 chip + `IMAGE_RETRY_REQUIRED` toast + 中止闸。
- `pickImages` 加 catch（`OPERATION_FAILED` toast；用户取消不算失败）。
- `canonicalGenerate` 输入图 mime 按真实 ext 查表（原硬编码 `image/png`，`.jpeg` 落错 mime）。
- 行为测试 4 用例（入仓/回灌/失败摘除/选择失败）。

**不修（记录）**：`couldAddImageFile = isGenerateImageModel && isVisionModel`（`paintingModelSelection.ts:32`），纯 T2I 模型的上传入口整个隐藏——这是产品语义门（T2I 无参考图概念），不是 bug；入口可见（生图+视觉模型）时参考图链路已全部打通。

## 问题 4：编辑已发消息加附件，直接"保存并发送"不带附件

**已修复。** 根因：`useMessageOperations.ts resendUserMessageWithEdit` 把渲染期闭包旧 `message` prop 传给 `startBranchResend`，后者按旧 `message.blocks` 收附件——编辑器新增的附件块（新 uuid）不在旧列表。非异步竞态（块提交已 await）。

- 修复：`startBranchResend` 单点重读锚点实体（`store.getState().messages.entities[id] ?? anchorMessage`），不另传 files（避免第二真相源）。
- 回退分支（fork 失败时原地重发）补用户可见信号：warn 日志 + toast `message.edit.branch_fallback`（原静默）。
- 行为测试 2 用例（新附件随分支重发上行 / 回退可见信号）。

## 事故披露（已闭环）

实施 #5 时用 pwsh 5.1 `Get-Content` 批量替换 UTF-8（无 BOM）文件引发编码损坏（ANSI 误解码），110 个修改文件中 50 个受损。已全部恢复并验证（残损扫描 damaged=0）：

- 44 个纯 lodash 文件 + useShortcuts.ts：`git checkout HEAD` + 安全重做替换（`[IO.File]` API）。
- **`messageThunk.ts`（含用户未提交 WIP）**：GBK 反演 + 按原始字节重建。代码行与反演文件逐字节核对一致；**注释四处在洞位置曾按上下文重建，后与会话起点（损坏前）留存的用户 WIP git diff 原文逐行比对，差异已修正为原文**（"合并挂载门"/"或工作模式轮"/"的 documents_extract"/"必拒。"）。现在整个 WIP hunk 与损坏前记录逐字一致。
- 其余用户 WIP 文件（ToolsSettings.tsx(+test)、agentTools.ts、topics.ts、KnowledgeService.ts、两 locale、documentExtractTool.ts、kernel-integration.md）不在批量替换的损坏集内，diff 完整健在。
- 5 个 session 编辑文件：checkout + 重做替换 + 重做编辑。

教训已固化：批量改 UTF-8 文件禁用 `Get-Content/Set-Content`，用 `[IO.File]` 或 node；批量替换前先确认目标文件集合不含未提交 WIP。
